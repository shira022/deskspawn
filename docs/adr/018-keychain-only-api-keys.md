# ADR-018: デスクトップの API キーは OS キーチェーンのみ（平文保存の廃止）

## Status
accepted

## Context

デスクトップ版は当初、OS キーチェーン（Windows 資格情報マネージャー等）に
API キーを保存し、キーチェーンが利用できない環境では `credentials.json` へ
**平文でフォールバック**していた（`save_api_key_to_file`）。この設計には次の問題があった。

- ユーザーが「安全に保存されている」と誤認しやすい一方、実際には平文がディスクに残る。
- UI の保存先表示が実態とずれやすく、起動後に「file」表示を復元できていない
  （bug #172: `apiKeyStorageMethod` が起動時に復元されない）。
- Web 版（評価用）は IndexedDB に平文保存する仕様だが、同意なく保存される点が
  プライバシー/セキュリティ文書の実態と噛み合っていなかった。

## Decision

1. **デスクトップの平文書き込み経路を削除**する。`save_api_key_to_file()` を削除し、
   キーチェーンが利用できない場合は `Err` を返す（UI にそのまま出せる日本語メッセージ）。
   保存先を表す `storage_method` は常に `"keychain"` として記録する。
2. **既存の平文キーを自動移行**する。読み込み時にキーチェーンへ保存し、**読み戻して
   一致検証**できた場合のみ平文を削除する。移行に失敗した場合は平文を削除せず、
   キーは返し（アプリは使える状態を保つ）、`legacy_plaintext = true` で残存を UI に伝える。
3. **`load_api_key_info`**（`{ key, method, legacyPlaintext }`）が保存先と平文残存を
   返す（`get_api_key_storage_method` のような読み取り専用プローブは持たない。
   キーはログにも出さない）。キーチェーンにキーがあってもレガシー平文ファイルが
   残っていれば `legacyPlaintext = true` を返し、残存を UI に伝える（**自動削除は
   しない** — そのファイルのキーが別プロバイダ用かもしれず、データ喪失を避ける
   ため）。残存の削除は新規コマンド `delete_legacy_plaintext_file`（冪等）を
   ユーザーの明示操作から呼ぶ。既存の `load_api_key`（キー文字列のみ）は互換の
   ため維持する。
4. 移行・読み込み判断は**純粋関数＋クロージャ注入**に切り出し、実キーチェーンに
   依存せずユニットテストする。
5. **Web（評価用）は平文保存を維持**するが、保存前に同意チェックを必須にする。
   加えて「このタブのみ（保存しない）」= メモリ保持モードを追加し、Tauri での保存
   失敗が IndexedDB の平文へフォールバックする穴を塞ぐ。

## Alternatives Considered

- **キーチェーン不可時は平文（現状維持）**: 誤認と平文残存のリスクが残るため却下。
- **平文を暗号化してファイル保存**: 鍵管理が別途必要で、OS キーチェーンという
  標準解があるのに車輪の再発明になるため却下。
- **キーチェーン不可時は保存自体を禁止し、キーを一切保持しない**: ユーザーが
  アプリを使えなくなるため却下。移行失敗時は「キーは返すが平文は消さない」を採用。
- **移行時に無条件で平文を削除**: 保存/読み戻しの検証前に消すとキーを失うため却下。
  必ず一致検証を挟む。
- **Web でもキーチェーンに保存**: ブラウザから OS キーチェーンへはアクセスできない。

## Consequences

- デスクトップは **平文を一切書かない**（キーチェーン必須）。要件として
  `docs/installation.md` に明記する。
- 既存ユーザーの平文キーは初回読み込み時に自動移行され、成功すれば平文は消える。
  失敗時は警告バナーと再試行導線が表示され、データ消失は起きない。
- キーチェーンにキーがある状態で旧平文ファイルが残っている場合も UI が残存を
  警告し、「平文ファイルを削除」操作で明示削除できる（自動削除は行わない）。
- UI の保存先表示は起動・再読み込み後も正しく復元される（bug #172）。
- Web は同意の上でのみ平文（IndexedDB）に保存し、タブのみモードも選べる。
