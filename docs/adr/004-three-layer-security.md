# ADR-004: 3層セキュリティモデルとハードニング

## Status
accepted

## Context
AIがコード生成・ファイル編集・シェル実行を行う性質上、悪意ある指示や不正なパス操作からユーザー環境を保護する必要があった。単一の防御策では不十分であり、多層防御が求められた。

## Decision
3層セキュリティモデルを採用する：
1. **テンプレート層**：生成起点を固定テンプレートに制限し、不正な構造の生成を防ぐ
2. **ASTガード層**：生成コードの構文解析により危険パターンを検出
3. **Freeform層**：自由生成はSecurity Serverのパス検証・コマンド許可リストを必ず通過させる

さらに依存インストールは `--ignore-scripts` を強制し、`execSync` を `execFileSync` に置換するなどのハードニングを実施する。

## Consequences
- パストラバーサル・不正シェル実行のリスクが大幅に低減
- 生成の自由度とセキュリティのトレードオフを層ごとに調整可能
- セキュリティ検証コードの保守コストが発生
