# ADR-012: 品質ループの標準装備（テスト駆動生成）

## Status
accepted

## Context
AIによるコード生成の最大の課題は「動くコードを安定して生成できるか」。従来の生成フローは、コード生成→型エラー検出（get_errors）→修正のループだったが、**実行時挙動（API・DBのCRUD等）の検証が不足**していた。特にフルスタック化（ADR-010）に伴い、バックエンドの正しさを機械的に検証する仕組みが必須となった。

## Decision
生成アプリに**品質ループを標準装備**する。

1. **テスト基盤の同梱**: デスクトップ版テンプレートに `bun test` を標準設定（`src/*.test.ts`）
2. **Hono `app.request()` の活用**: サーバー起動なしでAPIを直接テスト（ヘルスチェック・CRUD・バリデーション等）
3. **AIフローへの組み込み**: coderシステムプロンプトに「API/データコード生成後は必ず `bun test` を実行し、失敗なら修正して再実行（グリーンになるまで）」を必須指示として追加（デスクトップ版のみ）
4. 品質ループ: コード生成 → 自動テスト実行 → 失敗なら修正 → 再テスト

## Consequences
- 生成アプリのAPI/DBロジックの品質が機械的に保証される
- バックエンドの回帰バグを生成段階で検出可能
- coderプロンプトの指示が増えるが、デスクトップ版のみの追加でWeb版に影響なし
- テスト自体もAIが生成するため、テストの質は生成モデルの能力に依存（今後の改善余地）
