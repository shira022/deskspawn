# ADR-011: bunの同梱・初回展開

## Status
accepted

## Context
生成アプリの依存インストール・dev server起動・テストにはbunを使用する（ADR-010）。配布時にユーザーへNode.js等のランタイムインストールを強いるのは、セットアップ障壁が高い。一方、システム全体にランタイムをインストールする方式は、バージョン衝突やホスト環境の汚染リスクがある。

## Decision
**bun.exeをアプリに同梱し、初回起動時に `~/deskspawn/tools/bun/` へ展開**する。

- サイズ約100MBを許容し、オフラインでも初回セットアップが完結
- ユーザーのホスト環境（Node/npm）は一切変更しない
- 開発中は `dev/tools/bun/` を利用（配布時は同梱に切替）
- sidecarのbun解決は環境非依存の3段階: 1) `process.env.BUN_PATH`（明示指定を最優先、配布時の同梱bun切替にも使用）→ 2) PATH探索（Windows: `where bun` / Unix: `which bun`）→ 3) `os.homedir()` ベースの既定レイアウト。cwd非依存で起動
- 実ユーザー名入りの絶対パスのハードコードを排除（公開リポジトリへの情報混入と他マシンでの preview 失敗を防止）

## Consequences
- ユーザーはbunの存在を意識せずに、インストール・起動・テストが動作
- ホストのランタイム環境が常にクリーン（Windowsホスト最小化方針と整合）
- 同梱バイナリの更新はリリースごとの管理が必要
- 初回展開の失敗時は `~/deskspawn/tools/bun/` の再展開で復旧可能
