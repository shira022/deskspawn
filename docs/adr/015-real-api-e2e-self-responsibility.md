# ADR-015: 実API E2E テストの自己責任方針と漏洩対策

## Status
accepted

## Context
- デスクトップ版のユーザーフロー検証（E2E）は、ダミーモード（`DESKSPAWN_E2E_REAL` 未設定）で
  UI フローのみを検証していた。実API（実際のプロバイダーへの接続 → チャット応答 →
  プレビュー生成 → チェックポイント保存）の検証は、実APIキー無しでは物理的に不可能。
- 開発者ごとに環境が異なるため、「開発者がローカルで汎用的に検証できる」仕組みにする必要がある。
- API キーは**OS キーチェーン**に保存する前提（本番と同じ経路）とする。
  キーの保存・削除は**開発者側に委ねる**（自己責任）。コスト・漏洩リスクも開発者責任。
- 漏洩リスク（trace・シェル履歴・平文ファイル・CI 混入）を網羅し、自動/手動の対策を定める。

## Decision
1. **実API E2E は開発者自己責任**とする（`DESKSPAWN_E2E_REAL=1` で有効化）。
   - OS キーチェーン保存が前提。キーの保存・削除は開発者へ委ねる。
   - レート制限・低割当のキーを推奨。本番キーは禁止。CI では絶対に実API 不可（ダミーのみ）。
2. **キーの取り扱い**は環境変数 `.env`（gitignore 済み）からのみ。
   - シェル履歴に直接打たない（`set -a; source .env; set +a`）。
3. **漏洩対策（自動）**:
   - `playwright.config.ts`: `DESKSPAWN_E2E_REAL=1` 時は trace を `off`（キー/プロンプトが trace.zip に残らない）。
   - `pnpm test:e2e:real`: desktop 限定実行 + `scripts/clean-test-results.mjs` で test-results/playwright-report を事後削除。
   - credentials.json（file フォールバック）はユーザープロファイル内のみ。プロファイル外への保存は拒否。Windows では隠し属性付与。
4. **ドキュメント整備**: `docs/user-flow-spec.md`（Real-API E2E 節）・`CONTRIBUTING.md`・`README.md`・E2E ヘッダに、手順・自己責任・コスト注意・漏洩対策を明記。
5. **実API 検証の実行タイミング**: 実APIキーの設定は開発者が行う。キー設定後に指示があれば実行する（本ADR 採択時点では未実行）。

## Consequences
- ✅ 開発者が自分の環境で実API 検証を行える（自己責任・汎用的）。
- ✅ CI に対する実キー混入のリスクを構造的に排除（CI はダミーのみ・trace オフ・.env は gitignore）。
- ✅ trace / シェル履歴 / 平文ファイルからの漏洩を軽減。
- ⚠️ 実API 実行はコストが発生し得る（開発者責任で管理）。
- ⚠️ キー削除が漏れると OS キーチェーンに残り続ける（開発者責任・Post-run 手順で明記）。

---

## 🔒 個人情報・機密情報の禁止（必須）

- ❌ API キー・トークン・シークレットの実値を記載しない。
- ❌ 絶対パス・ユーザー名を記載しない（`~/` 相対表記 or 環境変数名のみ）。
